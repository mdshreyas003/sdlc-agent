# Scoreboard (ticket 03)

One command scores any system that returns the answer contract (`src/whycode/contract.py`) against the gold set and prints a results table per question type with 95% bootstrap intervals. Code: `src/whycode/eval/`. Tests: `tests/eval/`.

| Path | What it holds |
|---|---|
| `gold/human.yaml` | Human-written questions (drafts until `human_verified: true`) |
| `gold/window.yaml` | Hand-written Held-out Window questions (template inside) |
| `gold/automatic.yaml` | Generated by `whycode-eval labels`; never edit by hand except `human_verified` |
| `prompts/` | Committed prompts: `judge.md`, `llm_alone.md`, `rag_answer.md`, `git_agent.md`. Their hash is in every report |
| `results/<split>-<time>/` | One run: `manifest.json`, `answers.jsonl`, `verdicts.jsonl`, `scores.jsonl`, `report.md` (and `calibration.md` / `.svg` once drawn). Commit them |
| `judge_agreement/` | `labels.yaml` (hand-labelled answers) and `agreement.md` (latest agreement, copied into every report header) |

## Commands

Every command takes `--corpus <file.jsonl>` (or `WHYCODE_EVAL_CORPUS`) except `judge-sheet` and `agreement`. Real runs need `ANTHROPIC_API_KEY`; the embedding model downloads once to `.cache/fastembed`.

```sh
uv run whycode-eval labels --corpus data/corpus.jsonl --window-end 2025-06-30   # writes gold/automatic.yaml
uv run whycode-eval check  --corpus data/corpus.jsonl                           # every gold quote vs the corpus
uv run whycode-eval run --split dev --corpus data/corpus.jsonl \
    --systems ours=whycode.answer.systems:ours,ours-without-supersession=whycode.answer.systems:ours_without_supersession,llm-alone,vector-rag,git-agent \
    --reference ours --git-repo ~/src/cockroach --cutoff-rev d13253527955eaa2da09394b8a2729627ab25c48 --window-rev <sha>
uv run whycode-eval judge-sheet --run results/dev-<time> --n 20                  # answers to hand-label
uv run whycode-eval agreement                                                    # judge vs hand labels
uv run whycode-eval calibration --run eval/results/dev-<time>                    # confidence vs correctness plot
```

- `run --split dev --include-unverified` is a smoke run over drafts (dev only). Without it, only `human_verified` questions count, and a verified question that fails the gold check stops the run.
- `run --split test` is allowed once: it is refused while any `results/test-*` exists and while `prompts/` or `gold/` has uncommitted changes. `--resume results/test-<time>` finishes a stopped run with the same prompts, without asking any system twice.
- `--limit N` runs the first N questions.

## Plugging in a system

`--systems name=module:factory` imports `factory`, calls it with a `SystemContext` (corpus, cutoff, eval dir, answer and embedding model ids) and expects a `whycode.eval.runner.System` or a plain callable `Query -> Answer`. A system must honour the whole `Query`:

- `as_of`: answer from history up to that date; `None` means all history including the Held-out Window (the `@after` half of a window question).
- `exclude`: node ids to treat as absent (ablation and hidden answer keys).
- Return `Answered(answer, usage)` instead of a bare `Answer` to get a cost column; usage is a list of `ModelCall`s.

Our system (ticket 04): `ours=whycode.answer.systems:ours` and the ablation
`ours-without-supersession=whycode.answer.systems:ours_without_supersession` (same graph and composer, every
Decision treated as live). Both read Neo4j and the composer from the environment (`src/whycode/config.py`; set
`ANTHROPIC_API_KEY` so the composer is Opus 5.5, the baselines' answering model). The graph must hold the Held-out
Window: build it with `whycode build --cutoff <window end>` and write the corpus from that same graph
(`whycode.graph.corpus`); `as_of` and `exclude` are applied in every query pattern. The supersession catch rate of
the two systems on `supersession` and `window-after` cases is the "with and without supersession" difference. A
gold question without an `anchor` reaches our system as its words and goes through the entity-matching step (one
Opus 5.5 call, or a refusal with `WHY_COMPOSER=template`); our system does not report model usage yet, so its cost
column stays empty.

The four baselines (spec user story 32):

| `--systems` name | What it is |
|---|---|
| `llm-alone` | The answering model with no retrieval and no tools: the question, the Code Entity if named, and the as-of date (`prompts/llm_alone.md`). Its citations are unverified, so citation precision shows what it invents |
| `vector-rag` | Dense vector RAG over the same corpus (`prompts/rag_answer.md`) |
| `git-agent` | A tool-use agent over a git checkout at the cutoff (`prompts/git_agent.md`; needs `--git-repo`) |
| `ours-without-supersession=whycode.answer.systems:ours_without_supersession` | Our system with every Decision treated as live |

All of them use the same answering model (`claude-opus-5-5`) and, for vector RAG, the same embedding model (`BAAI/bge-small-en-v1.5`) as our system; the report warns when declared models differ.

## Calibration plot

`whycode-eval calibration --run <results dir>` reads a finished run (no model calls) and writes `calibration.md` (a table) and `calibration.svg` (one panel per system: answer correctness at each stated confidence, High / Medium / Low, with 95% bootstrap intervals and the number of answers) into the run directory; `--systems a,b` and `--out DIR` narrow it. Each answer that was not refused counts at its stated confidence, valued at its judged correctness, or 0 for an unanswerable question answered anyway; refusals and failed calls are left out and counted. "High" means something when its column is visibly above Medium's, with intervals that do not overlap much. Draw it on the dev split: the confidence thresholds (`src/whycode/answer/confidence.py`) are calibrated there, never on test.

## Corpus format (ticket 02 writes it)

One JSON object per line, a `whycode.eval.corpus.CorpusRecord`: `id`, `kind` (rfc, pr, issue, review, comment, commit), `title`, `text`, `url`, `date` (merge date for a Change, creation date otherwise; records after the cutoff are visible only to `@after` cases), `number`, `labels`, `paths`, `commits`. The `id` must be the node id the graph cites. The gold drafts assume `rfc:<file stem>`, `pr:<n>`, `issue:<n>`; the git-agent cites `commit:<full sha>`. Quotes are checked against `title` + `text`, word for word (whitespace collapsed, case ignored, nothing else forgiven: `whycode.eval.corpus.is_verbatim`).

## Gold question format

```yaml
- id: H-009                      # unique
  type: lookup                   # lookup | multi_hop | incident | supersession | unanswerable | trap | window
  origin: human                  # human | automatic
  question: Why does ...?        # how an engineer would ask; no PR numbers, URLs or hashes
  anchor: {kind: function, id: <code index id>}   # optional; our system gets it, baselines see it in the question
  answerable: true               # false for unanswerable and trap
  gold_facts: [<atomic fact a correct answer states>, ...]          # 1-4, each checkable against a quote
  gold_evidence: [{node_id: pr:123, quote: <verbatim, no "...">}]   # multi_hop needs two records
  superseded_facts: [<dead Decision a correct answer never presents as live>]   # supersession
  ablates: H-002                 # unanswerable by ablation: H-002's evidence is hidden from every system
  exclude: [rfc:...]             # extra node ids hidden for this question (e.g. the answer key)
  after: {gold_facts: [...], gold_evidence: [...], superseded_facts: [...]}     # window only
  split: dev                     # about 30% dev, 70% test; never tune prompts on test
  human_verified: false          # flip to true only after a human checked facts, quotes and type
  note: <how it was built and checked>
```

## Metrics (definitions in `src/whycode/eval/scoring.py`)

Answer correctness (fact-level judge), citation precision (cited node ids that resolve to a visible record, quotes verbatim), supersession catch rate (reports the change and presents no superseded fact as live), refusal accuracy, invented-answer rate (unanswerable cases answered anyway), latency and cost. Each per question type with a bootstrap interval (1000 resamples, seed 0), plus paired differences against `--reference`.
